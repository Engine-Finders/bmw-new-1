# architecture
- Route structure for BMW engines site: use /engine/[slug] for engines, and a catch-all [...slug]/page.js for models (1-segment), generations (2-segments), and variants (2-segments). Confidence: 0.70
- Prefers hard-coding URLs and configuration values directly in source code rather than using environment variables (e.g., `.env` files). Confidence: 0.85
- Prefers canonical URLs WITHOUT trailing slashes (e.g., `/engine/b37-b47` not `/engine/b37-b47/`). Confidence: 0.85
- Prefers clean URLs without a `.html` extension — static HTML pages should be served at extension-less paths (e.g., `/about` not `/about.html`). Confidence: 0.80
- In navigation menus, prefers listing all items flat/exhaustively rather than hiding them behind "View All" buttons. Confidence: 0.75
- Prefers the footer to carry only a curated subset of key links, not the full site inventory — if a link is already in the navbar, don't duplicate it in the footer (the navbar should be the single exhaustive source). Confidence: 0.85
- When you want precise control over canonical URLs in Next.js without metadataBase trailing-slash normalization, use absolute URLs (e.g., `https://bmwengines.uk/engine/${slug}`) rather than relative paths (`/engine/${slug}`) in the canonical field. Confidence: 0.80
- When generating sitemaps for Next.js, derive URLs from the same page registries that power the dynamic routes rather than scanning the filesystem or maintaining a separate URL list - this ensures the sitemap stays synced with actual pages automatically. Confidence: 0.75
- After making SEO/infrastructure changes, verify correctness by inspecting the actual generated output files (e.g., `.html` in `.next/server/app/`) rather than trusting only that the build passes. Confidence: 0.70
- All visible page content — including h1 and h2 headings — should come from JSON data files rather than being hardcoded in components. If any headings are still hardcoded, they should be extracted into the relevant JSON and referenced dynamically for consistency. Confidence: 0.75
- When a value is universal across all instances (e.g., CTA button URLs that always point to the same page), hardcode it directly in the component rather than routing it through per-page JSON data files. If every page uses the same value, it is a constant, not configuration — making it data-driven only creates busywork when the value changes. Confidence: 0.85
- Prefers CSS theming through custom properties (variables) defined in globals.css rather than hardcoded color values in component className strings. For shared interactive behavior (hover, transitions), use a reusable utility class (e.g., `.btn-cta`) in globals.css that references CSS variables instead of repeating Tailwind hover/transition utilities on every element. Centralized styling via variables keeps themes consistent and changeable in one place. Confidence: 0.75
